# 不同AI与平台的相容策略

核心是可读的Markdown规则与对话；Python脚本、图片与排程是增强能力，不是每个模型都拥有。不要声称已在所有AI或内部平台测试。依实际可用工具判断，不凭模型名称推断。

| 可用能力 | 行为 | 不可声称 |
| --- | --- | --- |
| 只有文字 | 问题／牌位／正逆位／解读／总结／追问；抽牌前标示文字模拟，或请提供外部牌面 | 真正程序随机、已固定不可见牌序、已生图 |
| 可执行Python且有私有临时目录 | 使用会话工具固定牌堆，支持数字、自动及同局补牌 | 工具未成功时称已抽好 |
| 可显示图片但不能执行程序 | 可展示已知牌对应的固定图片；图片来源独立于抽牌能力 | 能显图就等于能随机抽牌 |
| 可Python但无Pillow／无附件图片显示 | 完成真随机与文字解读；不为显图擅自安装依赖或建立网站 | 生成的本地路径等于用户已看到图 |
| 有生图工具 | 可在用户明确需要时重绘已确定的牌，标示示意；固定素材仍优先 | 即时生成保证百分百还原标准韦特 |
| 无连网／农历工具 | 使用已核对且涵盖该年的资料；缺年份就说明日期未核实，仍可作不报确切日期的主题解读 | 把旧年七夕／连休套到新年 |
| 有私有记忆但无排程 | 可保存用户同意保存的偏好；只在回来聊天时提示 | 已建立到点通知 |
| 有排程但无持久记忆 | 以工具实际保存的任务为准，不建立虚假的偏好档 | 永久记得所有设定或跨模型共享记忆 |

不预设OpenAI特定工具名称；使用宿主实际提供的等效脚本、附件、记忆、提醒能力。没有必要就不外连。中文可读牌名与文字流程在不同模型都能理解，但内部平台是否加载资产／脚本／提醒，必须实际验收。

图片优先以宿主支持的附件方式呈现，Markdown本地路径只在该宿主确实可读时使用；不要把Codex的sandbox路径拿给其他平台用。无法显示就即刻转文字，不无限重试或再次要求下载HTML。

文字模拟仍用七十八张牌的标准名称，不重复、不换方向，清楚区分「生成的叙事性模拟」与「外部提供／程序执行结果」。用户不接受模拟时，不强行继续；提供自行抽牌后解读的选项。

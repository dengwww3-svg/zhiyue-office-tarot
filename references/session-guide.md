# 固定牌堆、数字选牌与补牌

根目录为本技能目录；脚本使用Python 3.9以上的标准函式库，只有排图需要Pillow。不要把开发时的绝对路径照抄到另一个宿主。从当前宿主建立每个用户／对话独立的私有临时目录，用新的session档名；不放在技能目录或共用目录，不把整副隐藏牌序贴给用户。

## 执行顺序

假设STATE是当前私有临时文件的绝对路径（实际执行须自行替换，不把示例字串当路径）。

1. 问题、牌位与张数已确定后，`python3 scripts/tarot_session.py start --state STATE --question '本次问题与期间' --positions '现况' '阻碍' '建议' --layout row --mode auto`。这一步只洗牌，不揭牌。自动流程可在用户已确认开始后连续执行start和draw；数字模式改`--mode numbers`，必须在请用户选数字之前先start。
2. 自动抽：`python3 scripts/tarot_session.py draw --state STATE`；数字抽：`python3 scripts/tarot_session.py draw --state STATE --numbers 7 18 39`。用户选数字的原顺序就是牌位顺序。若选数字途中明确说改为自动，使用draw加`--auto`，保留同一副固定牌堆，不能偷偷重洗。选错时尚未draw，不重新start；只向用户核对修正的完整数列。
3. 使用stdout的固定结果显图并立即解读。不要把工具JSON原封不动当用户解读，也不要额外要求用户重新发送结果。
4. 明确追问后补牌：`python3 scripts/tarot_session.py add --state STATE --question '我主动邀约会如何' --parent 2`。parent是已揭牌的draw_id，可省略表示整体；默认自动补一张。用户想自己选补牌时，先show取得已用数字，再请选未用号码，add加`--numbers 51`。两至三张补牌使用明确`--count`且数字数量匹配。
5. 恢复本轮：`python3 scripts/tarot_session.py show --state STATE`。只输出已揭牌、已用号码、剩余张数与牌堆摘要，不暴露未抽牌及方向。
6. 新问题／换人：重新确认期间与牌位，建立新的STATE；不能覆盖旧档假装同一局，也不能把他人资料混入。

完整七十八张牌只洗一次，每张方向在洗牌时一并固定，补牌仍从原剩余牌选。`--upright-only`只在start时依用户选择指定；本轮开始后不能改方向规则。私有文件包含隐藏牌堆与原问题，仅供本次工具使用，别上传到公开素材区或共用Git。

## 用户自己的牌

已有牌名／照片时不用先启动程序也能解读。若需要后续排图或补牌，先核对每张对应assets/deck.json的card id及正逆位，再用：
`python3 scripts/tarot_session.py start --state STATE --question '问题' --positions '现况' '阻碍' '趋势' --provided c02:正位 s02:正位 c08:正位`。

这会保留用户牌面，从排除已出现牌的其他牌建立后续数字补牌序列。明说「原牌由你提供，补牌用数字剩余牌抽取」，不能声称是用户实体牌堆的原本顺序。仅在要实际补牌时按本次确认取牌。

牌名别称先对照语意：高塔／塔、星币／钱币、侍者／侍从等；不要自创第七十九张牌。韦特为力量VIII、正义XI，不能混用马赛次序。外部牌组、方向不清或重复的实体抽牌先澄清；不要默默修正或使用错误id。

## 错误处理

初始牌数不符、数字重复、0／79／小数、已用数字、无此父牌、已抽完、状态被改动或同时操作锁定，均拒绝且不写入新结果。错误不等于授权重洗。原state遗失就如实说明，不靠旧牌名猜测未抽牌。

脚本未提供背景推送，不保存生日设定，也不会自行产生解读。解读由当前AI依原问题与抽牌结果产生。数字选牌不赋予用户挑牌义的能力，随机结果也不代表能预测未来。
